# 课堂分享讲稿（约 8 分钟）

## 0:00-1:00 开场

如果旅馆不知道今晚有多少客人，能不能只在编译时固定所有房间安排？运行时才知道规模的数据、需要跨函数保存的对象，促使程序使用动态内存。今天把 malloc 看成入住，把指针看成钥匙，把 free 看成退房。类比只帮助理解，不能替代 C 的规则。

## 1:00-2:00 前世今生

C 在 20 世纪 70 年代初与 Unix 一起发展。动态内存解决运行期空间需求；标准接口让调用者与内部算法分离。Doug Lea 于 1987 年开始编写 dlmalloc；1989 年 ANSI C 标准化。后来 glibc 的多 arena 与 TCMalloc 的线程/CPU 缓存回应多线程竞争。malloc 不是一种固定算法，也不是每次都直接调用内核。

## 2:00-3:30 播放第 1-4 幕

先声明模型：128 B 固定池、8 B 头部、8 B 对齐、首次适配。A 申请 24 B，模型需要 32 B；返回有效载荷起点，不是头部起点。B、C 依次入住。这里 72 B 载荷占了 96 B。头部开销与对齐填充要区分，不能把所有额外空间统称为外部碎片。

## 3:30-5:00 播放第 5-7 幕，先让同学预测

释放 A、C，得到 32 B 与 64 B 两个空闲块。问：现在空闲共 96 B，申请 72 B 能否成功？先暂停，再揭晓：模型要求连续 80 B，而最大只有 64 B。空闲总量不等于最大可用块。B 还活着，不能跨过它拼接；这里没有压缩或移动存活对象。

## 5:00-6:00 播放第 8-10 幕

释放 B 后相邻块合并成 128 B，重复同样申请就成功。强调：真实分配器可能向系统继续申请内存，失败结论只针对这个固定池模型。free 结束对象生命周期，分配器仍可能缓存空间；它不会自动把指针变量清空。

## 6:00-7:00 真实 C 示例

打开 examples/dynamic_scores.c。指出四处：乘法前的 SIZE_MAX 检查；malloc 后的 NULL 检查；realloc 使用临时指针；结束时 free。增长后的新增元素要初始化。代码预期输出 count=5, sum=445, average=89.0。

## 7:00-8:00 自由实验与提问

切到自由实验，申请 13 B：8 B 头部 + 13 B 载荷 + 3 B 对齐填充 = 24 B。讨论为什么不能写到第 14 个字节。再加载碎片案例，请同学完成“失败 → 释放 B → 重试成功”。

## 可能被问到的问题

- **malloc 是系统调用吗？** 它是 C 库接口。分配器通常先复用已持有的内存，在需要时向操作系统申请更多。
- **malloc 会清零吗？** 不保证。calloc 会把存储的位清零；不要据此推断所有类型的零值表示。
- **free 后为什么内存占用没下降？** 分配器可能保留空间用于复用，是否归还操作系统取决于实现与布局。
- **把 p 设为 NULL 就没有悬空指针了吗？** 只改变 p；其他指向旧对象的别名仍不可使用。
- **为什么 realloc 用临时指针？** 非零大小扩容失败时原分配仍存在；直接覆盖会丢失唯一引用。成功后仅使用返回的新指针。
- **演示里的 8 B 是标准吗？** 不是，是为了能手算而选择的模型参数。
